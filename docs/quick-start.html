About These Instructions

Applies to: The next documentation-aligned Windows release identified by the authoritative GitHub release record.

Last reviewed: 2026-10-02.

Audience: First-time users, including people unfamiliar with PowerShell, containers, API keys, or SHA-256.

Draft: Final filenames, hashes, tested combinations, and known limitations must appear in the final release record before publication.

Make Three Independent Choices

  1. Docker Desktop or Podman Desktop runs TowerScout in a Linux container.
  2. CPU or a compatible NVIDIA GPU processes images. CPU is simpler; GPU can be faster.
  3. Google Maps or Azure Maps supplies maps and imagery. One working provider is enough.

These supported options are not assigned by project support. If unsure, start with Docker CPU. You may choose another combination when its requirements are met.

Prepare The Computer

  1. Open Settings > System > About. Confirm Windows 11 and 64-bit operating system, x64-based processor.
  2. Compare Installed RAM with the final release's tested minimum.
  3. In File Explorer, open This PC. Plan at least 15 GB free for CPU or 35 GB for CUDA, plus room for exports.
  4. Select the Windows Start button, type Windows PowerShell, and open Windows PowerShell. Use the normal window; do not select Run as administrator unless a step explicitly requires it. Run wsl --status.

Windows Subsystem for Linux 2 (WSL 2) is the Windows feature that lets Docker or Podman run TowerScout's Linux container. If WSL is missing, use Microsoft's WSL installation guide. Enabling Windows features or restarting may require Local IT approval.

Docker

Follow Docker's Windows installation instructions, confirm your organization's licensing policy, use the WSL 2 Linux-container backend, and start Docker Desktop.

docker --version
docker compose version

Podman

Follow Podman Desktop's Windows installation instructions. Podman runs TowerScout inside a Linux virtual machine. Rootless means that machine runs containers without the Linux root administrator account.

First check whether a machine already exists:

podman machine list
podman system connection list

Only when no machine exists, create the default rootless WSL 2 machine:

podman machine init --now podman-machine-default

The tested path also needs 64-bit Python 3.12 to install its package-local Compose provider, the helper Podman uses to read TowerScout's container configuration. Install it from the official Python Windows downloads if permitted, then run python --version.

Optional NVIDIA GPU

Record the exact GPU from Task Manager or Device Manager, run nvidia-smi, and compare the GPU, driver, WSL, and engine with the final tested-support list. Use the -cuda128 package only when it matches. Maxwell and Pascal must use CPU. Never install a Linux NVIDIA display driver inside WSL.

Podman GPU additionally requires NVIDIA Container Toolkit and Container Device Interface (CDI) configuration inside the intended rootless machine. After verifying and extracting the package, follow the Podman GPU guide before setup.

One Map Credential

Prepare one Google Maps API key or Azure Maps subscription key. TowerScout currently uses one credential per provider for both browser and application requests, and the browser can see it. Do not create separate browser/server keys for TowerScout. Use a dedicated limited account, API restrictions, quotas, alerts, monitoring, and rotation.

Google Maps

  1. Sign in to the Google Cloud Console; create or select an organization-owned project and attach an approved billing account.
  2. Enable Maps JavaScript API, Places API (New), Maps Static API, and Geocoding API. TowerScout's current autocomplete control requires Places API (New).
  3. Open Google Maps Platform > Credentials, create an API key, and give it a TowerScout-specific name.
  4. Under API restrictions, restrict the key to only those four APIs.
  5. TowerScout sends the one key from both the browser and local application service. A Website restriction cannot cover the server requests, and an IP-address restriction cannot cover the browser requests. The compatible one-key setting is Application restrictions: None. If an application restriction is required, stop and use Azure Maps; this release cannot accept separate Google browser/server keys.
  6. Add quotas, alerts, monitoring, and rotation.

Use Google's official getting-started, key-creation, and security guidance and Place Autocomplete prerequisite.

Azure Maps

  1. Sign in to the Azure portal with an approved subscription and resource group.
  2. Create an Azure Maps account, accept its terms, and use the current Gen2 tier unless your organization directs otherwise.
  3. Open Settings > Authentication and copy the Primary Key to a temporary private location. Retain the Secondary Key for controlled rotation.
  4. Configure required budgets, alerts, monitoring, and rotation.

TowerScout currently uses the shared subscription-key method, not Microsoft Entra ID. Use Microsoft's account-and-key walkthrough and authentication guidance.

Unsigned-Package Safety

Important: unsigned scripts. TowerScout's PowerShell scripts are intentionally unsigned. Use the supplied .cmd and .bat entrypoints. Their process-scoped setting does not change the computer's permanent execution policy.

Stop if Windows or your organization's policy blocks this package. Confirm the package source and obtain the required approval; do not work around the control.

The standard package does not support computers requiring a trusted Authenticode publisher, WDAC/AppLocker approval, constrained-language approval, antivirus/EDR exceptions, or organization-specific allowlisting. Do not weaken persistent policy, endpoint protection, or TLS verification.

1. Create A Folder And Download Four Files

  1. In File Explorer, create and open Documents\TowerScout.
  2. Open the TowerScout Releases page.
  3. Select the entry whose notes identify it as the current supported final Windows release. Stop if none does.
  4. From GitHub's Assets list, download one -cpu.zip or -cuda128.zip, its .zip.sha256, the shared -assets- ZIP, and its .zip.sha256.
  5. Move the four files into Documents\TowerScout.

Do not use the green Code button or GitHub's Source code archives. GitHub Assets means the download list. The Model & Data Package is the shared -assets- ZIP. Docker or Podman downloads the container image later; a dataset.zip is user output, not an installer.

2. Verify Both ZIPs Before Extraction

SHA-256 is a file check value. For each ZIP, the local value, downloaded sidecar, and value printed in the final release notes must match.

Open this folder: In File Explorer, open Documents\TowerScout, click its address bar, type powershell, and press Enter.

CPU input:

$appZip = Get-ChildItem -File "*-cpu.zip"
$assetZip = Get-ChildItem -File "*-assets-*.zip"
Get-FileHash -Algorithm SHA256 -LiteralPath $appZip.FullName
Get-Content -LiteralPath ($appZip.FullName + ".sha256")
Get-FileHash -Algorithm SHA256 -LiteralPath $assetZip.FullName
Get-Content -LiteralPath ($assetZip.FullName + ".sha256")

NVIDIA GPU input: use the same block, but replace its first line with:

$appZip = Get-ChildItem -File "*-cuda128.zip"

Expected output: two calculated hashes and two sidecar lines. Compare all 64 characters for each ZIP with the matching public release value. Stop if any value is missing/different or more than one ZIP matches. Do not extract, unblock, or run the file.

Only after both ZIPs pass may you use Properties > Unblock on the Application Package ZIP if Windows shows that checkbox.

3. Extract The Application Package

Right-click only the verified -cpu.zip or -cuda128.zip, select Extract All, and extract it inside Documents\TowerScout. Do not extract the Model & Data ZIP.

The new folder should contain:

setup-towerscout.cmd
start.bat
scripts\
docs\
assets\
compose.yaml

The local assets folder begins empty. Leave the Model & Data ZIP and sidecars one folder above it.

4. Run Setup For Your Choice

Open this folder first: Open the extracted folder in File Explorer, click the address bar, type powershell, and press Enter. A command starting with .\ runs a file from this folder. Keep the window open.

Podman users then install and confirm the package-local Compose provider:

.\scripts\install-podman-compose-provider.cmd -Apply
podman compose version

Podman GPU users must also complete the version-matched CDI preparation in the Podman GPU guide. After extraction, run the package-local check below. The GPU helper is the guide's documented, limited .ps1 exception:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-podman-gpu.ps1 -VerifyOnly

If it says provisioning is required, use the guide's explicit provisioning step, repeat -VerifyOnly, and continue only after it reports nvidia.com/gpu=all.

Docker CPU

.\setup-towerscout.cmd -Engine docker -Gpu off

Docker NVIDIA GPU

.\setup-towerscout.cmd -Engine docker -Gpu on

Podman CPU

.\setup-towerscout.cmd -Engine podman -Gpu off

Podman NVIDIA GPU

.\setup-towerscout.cmd -Engine podman -Gpu on

The first image pull can take several minutes. Setup checks package data, imports hash-verified assets, downloads the digest-pinned image, starts TowerScout, and normally opens http://localhost:5000. setup_required is normal until provider setup is saved.

If ZIPs are elsewhere, copy their full paths from File Explorer and replace the bracketed explanatory text; do not type the brackets. The example below is Docker CPU. Preserve the -Engine and -Gpu values from the setup card you chose. Copy the whole multiline command. Backticks mean the command continues, and quotes keep paths with spaces together.

.\setup-towerscout.cmd `
  -Engine docker `
  -Gpu off `
  -PackageZip "[full path copied from the Application Package ZIP]" `
  -AssetZip "[full path copied from the Model & Data Package ZIP]"

5. Configure One Provider

  1. Paste the Google or Azure credential you prepared into its Setup Wizard field.
  2. Validate it.
  3. Select that provider as the default.
  4. Save setup.

One provider is enough. Do not include the key in a screenshot, issue, email, chat, log, or trace.

.\scripts\status.cmd -Engine docker -Port 5000

Use podman if selected. ready means provider setup and required assets are present. degraded needs recovery; fatal is a stop condition. For NVIDIA GPU, status must also show selected_device=cuda; ready alone does not prove GPU processing.

6. Try A Small First Search

  1. Search for a familiar public, non-sensitive place or move the map there.
  2. The circle radius field uses metres. Enter a small radius, choose Circle, and click the map. For a polygon, choose Custom shape and click its corners. Double-click to finish on Azure Maps; right-click outside the shape to finish on Google Maps.
  3. Select Estimate tiles. Reduce the area until the first run estimates only 1-6 tiles.
  4. Select Find towers and wait for completion.
  5. Review the map/list. Zero detections can be valid and does not itself mean installation failed.
  6. Export important results before closing or stopping.

A successful first use reaches ready, loads the chosen map, completes the small request without an error, and updates the review panel. Formal release fixtures/counts are maintainer work, not an end-user requirement.

7. Record, Stop, Or Reopen Your Setup

Record the application folder, engine, CPU/GPU mode, provider, port, and browser address. Never record the credential.

Stop when finished

Run only the line for your engine:

.\scripts\stop.cmd -Engine docker
.\scripts\stop.cmd -Engine podman

Start or reopen later

For Podman, run podman machine list first. Run podman machine start podman-machine-default only if the recorded machine is stopped. Then run only the matching start command:

Docker CPU

.\start.bat -Engine docker -Gpu off

Docker GPU

.\start.bat -Engine docker -Gpu on

Podman CPU

.\start.bat -Engine podman -Gpu off

Podman GPU

.\start.bat -Engine podman -Gpu on

stop.cmd has no port option. If you use port 5001, add -Port 5001 to setup, start, and status, then open http://localhost:5001.

Normal stop/start and reboot preserve the selected engine's named volumes, engine-managed storage areas for configuration, assets, sessions, temporary review data, uploads, cache, and logs. Docker and Podman stores are separate. Internal session storage is not a backup; export important work. Never use volume deletion, prune, Podman machine reset, or blanket cleanup as routine recovery.

Get Help Safely

.\scripts\status.cmd -Engine docker -Port 5000
.\scripts\logs.cmd -Engine docker -Tail 200

Use the recorded engine/port and review logs locally. Local IT owns Windows policy, installation, proxy, TLS, and managed-device issues. A certificate error requires the separate Local IT dry-run/review/apply path; do not disable verification.

For a non-sensitive TowerScout defect, use the public issue tracker. It is not a private or guaranteed-response help desk. Never post keys, .env, raw logs/screenshots, browser traces, private locations, provider responses, certificate details, uploads, exports, or volume contents.
