Before Using This Guide

Applies to: The exact documentation-aligned Windows release. Last reviewed: 2026-10-05. Audience: Users after first setup.

This guide applies to Docker CPU, Docker GPU, Podman CPU, and Podman GPU when the chosen path meets the final release's requirements. The user chooses the engine, processing mode, and map provider.

  • The chosen engine is installed, permitted, and running.
  • Model and ZIP-code assets are imported.
  • TowerScout opens at the recorded localhost address.
  • At least one Google or Azure credential is configured.

If not, use the Quick Start. Use supplied .cmd/.bat wrappers on computers where the unsigned package is permitted. Never weaken persistent execution policy, endpoint protection, or TLS verification.

Required GPU mode must show selected_device=cuda. A host-only nvidia-smi result or CPU fallback is not a GPU success. Refresh Podman CDI after a Windows NVIDIA driver update.

Normal Workflow

  1. Choose Google Maps or Azure Maps.
  2. Search or move the map to a public/non-sensitive location.
  3. Define a search area.
  4. Estimate tiles, then run detection.
  5. Review detections and add manual corrections if needed.
  6. Export important results.

TowerScout suggests possible towers for human review. It does not replace field confirmation, environmental assessment, or public-health judgment.

Choose A Provider And Navigate

One valid Google or Azure credential is enough. If both are configured, use the provider selector for the current workflow. Search by address, city/neighborhood, or ZIP code, or pan and zoom manually. ZIP search requires imported ZIP-code data.

The current one-key-per-provider design exposes the configured credential to browser code. Never place a key, .env, browser trace, provider response, or key-bearing screenshot in a support record.

Define A Search Area

Circle

  1. Search for or navigate to the location.
  2. Enter a radius in meters.
  3. Select Circle.
  4. Click the map to place the circle.

Custom Polygon

  1. Select Custom shape.
  2. Click each corner around the search area.
  3. On Azure Maps, double-click to finish. On Google Maps, right-click outside the shape to finish.

A custom search area tells TowerScout where to detect. It is different from a manual tower polygon added during review.

Estimate And Detect

  1. Select Estimate tiles. It shows expected tile count and approximate time.
  2. If the area is larger than intended, clear it and draw a smaller one.
  3. Select Find towers.
  4. Watch the progress overlay while TowerScout downloads imagery, detects, classifies, removes duplicates, and geocodes.

You may cancel an active run. Wait until the application returns to idle before starting another. A zero- detection result can be valid and is not by itself an installation failure.

Review And Correct Results

Use the detection list to select/highlight a result, uncheck a likely false positive, adjust the minimum confidence slider, switch Find/Label review modes, and step through results. The slider affects what is visible and exported.

Add Manual Towers

  1. Run detection first.
  2. Select Add Towers and draw around a missed or confirmed tower.
  3. Complete the polygon: double-click on Azure, or right-click outside on Google.
  4. Select Save Towers.

Clear removes unsaved drawing shapes. Clear all removes all manual tower detections. Unchecking one saved detection excludes that item from export. These actions are not equivalent.

Export And Restore

Privacy: Confirm the approved destination before selecting a download. Dataset ZIPs can contain sensitive locations, imagery, and investigation context. Store and share them only under the site's approved procedure. Export important work before stopping; internal sessions are not backups.

  • Download results creates detections.csv and detections.kml.
  • Download dataset creates dataset.zip with tiles, labels, metadata, and manual additions.
  • Restore dataset reloads a prior dataset.zip; then verify provider, map, detections, and manual towers.

Stop When Finished Or Resume Later

Stop when finished

Run only the line for your engine:

.\scripts\stop.cmd -Engine docker
.\scripts\stop.cmd -Engine podman

Start or resume later

For Podman, run podman machine list first. Run podman machine start podman-machine-default only if the recorded machine is stopped. Then run only the matching start command:

Docker CPU

.\start.bat -Engine docker -Gpu off

Docker GPU

.\start.bat -Engine docker -Gpu on

Podman CPU

.\start.bat -Engine podman -Gpu off

Podman GPU

.\start.bat -Engine podman -Gpu on

stop.cmd has no port option. Add a non-default port to setup/start/status and the browser URL.

Normal stop/start and reboot retain the selected engine's named volumes, engine-managed storage areas for settings, assets, sessions, and other application data. Docker and Podman have separate stores; changing engines does not migrate settings or assets. Do not use volume deletion, prune, or Podman machine reset as ordinary recovery.

Getting Help

Use Local IT for Windows policy, software installation, proxy, TLS, or managed-device problems. For a reproducible non-sensitive TowerScout defect, use the public TowerScout issue tracker. It is not a private or guaranteed-response help desk.

Include release/package name, Docker/Podman, CPU/GPU, port, sanitized readiness, failed step, and a non-secret error category. Never post keys, .env, raw logs/screenshots, traces, private locations, provider responses, certificates, uploads, exports, or volume contents.
