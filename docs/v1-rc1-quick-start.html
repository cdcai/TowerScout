TowerScout V1 RC1

Quick Start

The short Windows pilot path for extracting the package, importing assets, launching TowerScout, completing setup, and confirming readiness.

Steps

Prerequisites Download Verify Extract Initialize Assets GPU Boundary Setup Confirm Success Source/licenses Help

Before You Start

Confirm Windows 11 AMD64, Windows PowerShell, a modern browser, normal outbound internet access, enough disk space for the package/assets/container image, and one valid site/user-owned provider key.

Install one supported container engine: Podman with a running Podman machine and Compose provider, or Docker Desktop where it is licensed, approved, installed, and running.

You do not need Git, Python, Conda, Node.js, VS Code, or a source-code checkout for the normal package path.

If Docker Desktop or Podman is not already installed and approved on your workstation, or if you do not already have a valid restricted provider key, stop here and contact your site administrator or support lead before continuing.

If both Docker and Podman are installed, use -Engine podman consistently when validating the Podman path.

Download The Release Files

Use the control ZIP, control checksum, asset ZIP, and asset checksum for the same release version. The exact filenames can change by release.

Verify Downloads Before Extracting

Compare each ZIP to its matching .sha256 file before extracting either package. If either SHA-256 value does not match, stop and obtain a fresh copy of the release artifact.

Get-FileHash .\towerscout-v0.1.0-rc1.zip -Algorithm SHA256
Get-Content .\towerscout-v0.1.0-rc1.zip.sha256
Get-FileHash .\towerscout-v0.1.0-rc1-assets-*.zip -Algorithm SHA256
Get-Content .\towerscout-v0.1.0-rc1-assets-*.zip.sha256

Extract The Control Package

Extract the control ZIP to a normal local folder such as C:\Users\<you>\TowerScout-v0.1.0-rc1. The folder should contain start.bat, Compose files, scripts\, docs\, and an empty assets\ folder.

Initialize The Package

.\start.bat

The first launcher run creates .env, starts the selected engine, polls readiness, and opens http://localhost:5000. If support tells you to use Podman, run .\start.bat -Engine podman and reuse that engine value on helper commands.

Stage And Import Assets

Extract the asset ZIP root entries into the package assets\ folder so it contains model_params\, data\, and asset_manifest.v1.json.

.\scripts\import-assets.cmd -Source assets
.\scripts\import-assets.cmd -Source assets -VerifyHashes

If TowerScout was started on a non-default port, pass the same port to the asset importer.

.\scripts\import-assets.cmd -Source assets -Port 5001 -VerifyHashes

The importer uses the selected engine's named volumes and restarts TowerScout after copying assets so imported model files are available before the first detection run.

GPU Boundary

The default launch is CPU-safe. Optional Docker GPU launch uses -Gpu auto or -Gpu on only after workstation-specific NVIDIA Docker validation. Podman GPU launch is not validated for V1 RC1.

Complete Setup

Use Setup Wizard or Settings to configure one valid Google Maps or Azure Maps key. Browser map SDK keys are client-visible, so V1 RC1 expects site/user-owned restricted keys.

Confirm Success

.\scripts\status.cmd

Readiness should become ready after provider setup and required assets are present.

Source, Licenses, And Help

Settings includes Resource Links for Project Overview, User Guide, Source/licenses, Video Guides, and the research article. The formatted source/license browser page is available at /license. Plain-text combined notices are available at /license.txt for scripts, copy/paste, or archival use.

If Something Fails

.\scripts\status.cmd
.\scripts\logs.cmd -Tail 200

Do not share provider keys, .env, raw screenshots, browser traces, raw logs, datasets, or sensitive AOIs unless your site has approved handling.
