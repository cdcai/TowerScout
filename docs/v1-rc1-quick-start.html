TowerScout V1 RC1

Quick Start

The short Windows pilot path for extracting the package, importing assets, launching TowerScout, completing setup, and confirming readiness.

Before You Start

Confirm Windows 11 AMD64, Windows PowerShell, a modern browser, normal outbound internet access, at least 15 GB free disk space, and one valid site/user-owned provider key. 25 GB free is a better target for first setup.

Application Package means the smaller app/control ZIP with scripts, docs, Compose files, and release metadata. Model & Data Package means the larger asset ZIP, also called the asset bundle, with model weights and ZIP-code data.

Docker Desktop with the WSL 2 backend is the primary V1 RC1 pilot engine. During Docker Desktop installation, keep the WSL 2 backend selected when prompted, start Docker Desktop from the Windows Start menu, and wait until Docker Desktop reports that it is running.

Docker's current Windows requirements include WSL 2.1.5 or later, 8 GB RAM, and hardware virtualization enabled in BIOS/UEFI. If your workstation is managed by IT, ask your site administrator before installing WSL, Docker Desktop, Podman, or provider credentials.

wsl --status
wsl --list --verbose
docker --version
docker compose version

Expected result: WSL is installed, any listed Linux distribution uses version 2, and Docker commands print version information while Docker Desktop is running.

Podman is a qualified package-runtime option only when support tells you to use it and the workstation already has a running Podman machine plus a working Compose provider such as podman-compose.

You do not need Git, Python, Conda, Node.js, VS Code, or a source-code checkout for the normal package path.

Unless support has explicitly assigned you the Podman path, stop here and contact your site administrator or support lead if Docker Desktop is not already installed and approved on your workstation. Also stop if you do not already have a valid restricted provider key.

If both Docker and Podman are installed, the launcher can choose Docker first. If support tells you to use Podman, use -Engine podman consistently on every helper command.

Stop And Contact Support

Stop before continuing if Docker Desktop is not installed, not approved, or cannot start unless support explicitly assigned you the Podman path; WSL is unavailable or shows version 1 without administrator approval to update it; a checksum does not match; asset import reports missing, corrupt, or hash-failed files; TowerScout reports fatal; or provider validation repeatedly fails after you confirm the key is correct.

Do not share provider keys, .env, raw logs, raw screenshots, private AOIs, browser network traces, cached provider responses, or exported datasets unless your site has an approved handling procedure.

How To Run Commands

Use Windows PowerShell, not the WSL/Ubuntu terminal, for package commands. Open File Explorer, open the extracted TowerScout package folder, click the address bar, type powershell, and press Enter.

Expected result: a PowerShell window opens with the package folder in the prompt. Paste one command at a time and press Enter. Commands that start with .\ run scripts from that folder.

Get The Release Files

Open https://github.com/J-Schulein/TowerScout/releases in your browser, then open the exact release that support told you to use. If support provides a direct release URL, use that link.

In the release Assets section, download all four TowerScout release files into a new empty local folder, such as C:\Users\<you>\Downloads\TowerScout-v0.1.0-rc1.

Download the Application Package ZIP, Application Package checksum, Model & Data Package ZIP, and Model & Data Package checksum from the same release. Do not use the green GitHub Code button or GitHub's automatic Source code (zip) or Source code (tar.gz) downloads for normal pilot setup.

The release version must match between the Application Package and the Model & Data Package. If the versions differ, stop and download the matching files from the same GitHub release.

Verify Downloads Before Extracting

Compare each ZIP to its matching .sha256 file before extracting either package. Run these commands from the new folder that contains only the four downloaded release files. If either SHA-256 value does not match, stop and obtain a fresh copy of the release artifact.

Get-FileHash .\towerscout-v0.1.0-rc1.zip -Algorithm SHA256
Get-Content .\towerscout-v0.1.0-rc1.zip.sha256
Get-FileHash .\towerscout-v0.1.0-rc1-assets-*.zip -Algorithm SHA256
Get-Content .\towerscout-v0.1.0-rc1-assets-*.zip.sha256

The hash from Get-FileHash must match the value in the matching .sha256 file. Uppercase and lowercase are not important, but the letters and numbers must otherwise be the same. The wildcard should match exactly one Model & Data Package ZIP and one matching checksum file; if it prints more than one, move old TowerScout downloads out of the folder and run the commands again.

Extract The Application Package

Extract the Application Package ZIP to a normal local folder such as C:\Users\<you>\TowerScout-v0.1.0-rc1. The folder should contain bootstrap.cmd, start.bat, Compose files, scripts\, docs\, and an empty assets\ folder.

Run The Guided Bootstrap

For first setup, use bootstrap.cmd. It checks disk space, port availability, Docker or Podman readiness, Compose availability, release metadata, checksum sidecars, and asset ZIP layout before importing assets and launching TowerScout. It verifies the Application Package checksum only when -PackageZip is provided and verifies the Model & Data Package checksum only when -AssetZip is provided.

Replace <asset-version> with the exact filename text from the Model & Data Package ZIP you downloaded. Do not type the angle brackets.

.\bootstrap.cmd -Engine docker -Gpu off -AssetZip .\towerscout-v0.1.0-rc1-assets-<asset-version>.zip

If the ZIPs are still in Downloads, either copy the Model & Data Package ZIP and its .sha256 file into the package folder, or pass the full path to -AssetZip.

.\bootstrap.cmd -Engine docker -Gpu off -PackageZip C:\Users\<you>\Downloads\towerscout-v0.1.0-rc1.zip -AssetZip C:\Users\<you>\Downloads\towerscout-v0.1.0-rc1-assets-<asset-version>.zip

Expected result: PowerShell prints TowerScout bootstrap preflight, reports prerequisite checks, verifies Application Package and Model & Data Package checksums only for the ZIP paths passed with -PackageZip and/or -AssetZip, imports valid assets with hash verification, starts TowerScout, and opens http://localhost:5000. If the browser does not open, leave PowerShell open and manually open that URL.

TowerScout bootstrap preflight
[OK] Engine docker is available
[OK] Compose is available
[OK] Model & Data Package checksum matched
[OK] Asset import completed with hash verification
[OK] TowerScout responded at http://localhost:5000
readiness: setup_required

setup_required is normal before provider setup is complete. After provider setup and asset import are complete, readiness should become ready.

The first launch may download the TowerScout container image from GHCR. This can take several minutes. Keep the PowerShell window open while Docker downloads and starts the image.

If support tells you to use Podman, run .\bootstrap.cmd -Engine podman -Gpu off -AssetZip .\towerscout-v0.1.0-rc1-assets-<asset-version>.zip and reuse that engine value on helper commands.

Manual Asset Import Fallback

Use this section only if support tells you not to use bootstrap.cmd -AssetZip, or if you already extracted the Model & Data Package manually.

Extract the Model & Data Package ZIP root entries into the package assets\ folder so it contains model_params\, data\, and asset_manifest.v1.json directly inside assets\.

If you see assets\assets\model_params, the files are nested one level too deep. Move the inner model_params, data, and asset_manifest.v1.json entries up one level before importing. If you are unsure, stop and ask support.

.\scripts\import-assets.cmd -Engine docker -Source assets -VerifyHashes -RestartWaitSeconds 180

If TowerScout was started on a non-default port, pass the same port to the asset importer.

.\scripts\import-assets.cmd -Engine docker -Source assets -Port 5001 -VerifyHashes -RestartWaitSeconds 180

The importer uses the selected engine's named volumes. If .env is missing, it initializes that file from the package .env.example before starting the selected container stack. It restarts TowerScout after copying assets so imported model files are available before the first detection run. Expected result: the command finishes without missing/corrupt asset errors and waits for TowerScout after restart.

GPU Boundary

The default launch is CPU-safe. Optional Docker GPU launch uses -Gpu auto or -Gpu on only after workstation-specific NVIDIA Docker validation. Podman GPU launch is not validated for V1 RC1.

Complete Setup

Use Setup Wizard or Settings to configure one valid Google Maps or Azure Maps key. Browser map SDK keys are client-visible, so V1 RC1 expects site/user-owned restricted keys.

Confirm Success

.\scripts\status.cmd -Engine docker

Readiness should become ready after provider setup and required assets are present. For a smoke check, support should provide the fixture before UAT starts: provider, public/non-sensitive location name, expected tile range, and whether zero detections is acceptable. Do not choose a private investigation AOI for the first smoke test. Estimate tiles first, keep the run small, then select Find towers. The default RC1 Azure smoke fixture is about 8 tiles.

Expected result: the detection workflow completes without crashing. For the default RC1 Azure fixture, expect a non-zero tower result. Exact counts may vary, but zero towers, no review-panel update, or a crash should be reported as BLOCKED or FAIL. For any future support-approved fixture, follow the zero-detection rule support provided for that fixture.

Stop Or Restart

.\scripts\stop.cmd -Engine docker
.\start.bat -Engine docker -Gpu off

Provider setup and imported assets are stored in named volumes and should survive container restarts. Always use the same -Engine value you used during setup. Docker Desktop and Podman use separate local storage, so switching engines can make setup or imported assets appear to be missing.

Source, Licenses, And Help

Settings includes Resource Links for Project Overview, User Guide, Source/licenses, Video Guides, and the research article. The formatted source/license browser page is available at /license. Plain-text combined notices are available at /license.txt for scripts, copy/paste, or archival use.

If Something Fails

.\scripts\status.cmd -Engine docker
.\scripts\logs.cmd -Engine docker -Tail 200

Send only support-requested, reviewed/redacted excerpts from log output. Do not send raw logs unless your site has an approved handling procedure.

For fuller troubleshooting and support details, open the package guide at /docs/v1-rc1-package-guide.md.

For package/image metadata, support may ask you to copy the package folder name and the contents of IMAGE.txt.

Get-Content .\IMAGE.txt

If PowerShell says a command is not recognized, confirm the prompt is open in the extracted TowerScout package folder and that the command starts with .\. If Docker commands are not recognized, open Docker Desktop from the Start menu and wait until it reports that it is running.

Do not share provider keys, .env, raw screenshots, browser traces, raw logs, datasets, or sensitive AOIs unless your site has approved handling.
