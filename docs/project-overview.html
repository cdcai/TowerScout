TowerScout release package

Project Overview

TowerScout is a local web application for identifying likely cooling towers from satellite and aerial imagery during investigation and registry-building workflows.

Document Metadata

Applies to: Current V1 package path through the stable v0.1.0 closeout, unless release notes say otherwise.

Last reviewed: 2026-07-08.

Audience: Pilot users, support leads, and release reviewers.

Runtime scope: The CPU Application Package is the primary path; the CUDA 12.1 Application Package, Podman CPU, Docker GPU, and Podman GPU are support-assigned paths after workstation-specific engine, Compose-provider, and NVIDIA validation.

What The Package Provides

The package provides a Windows-first local pilot path with a CPU Application Package ZIP for normal users, a CUDA 12.1 Application Package ZIP for support-validated NVIDIA GPU workstations, one shared Model & Data Package ZIP, pinned GHCR image digests, Docker Desktop primary pilot runtime configuration, CPU-safe default launch, optional Docker and Podman GPU controls, setup and support helper scripts, package-local docs, and release notices.

The normal pilot path is package-based. Source checkout, Python virtual environment, and Conda setup guides are legacy support material.

What Users Need Installed

Pilot users need Windows 11 AMD64, PowerShell, a modern browser, normal outbound internet access, WSL 2 and hardware virtualization support for Docker Desktop, and Docker Desktop installed, approved, and running as the primary pilot engine.

Plan for at least 15 GB of free disk space for the CPU package; 25 GB is a better first-setup target for CUDA validation.

Podman is a qualified support path only when support tells the user to use it and the workstation already has a running Podman machine plus an approved Compose provider. Users also need one site/user-owned restricted Google Maps or Azure Maps provider key.

The package path does not require Git, Python, Conda, Node.js, VS Code, or a source-code checkout.

Main Workflow

  1. Open the TowerScout GitHub Releases page, select the exact release support provided, and download the assigned Application Package variant, the shared Model & Data Package, and matching checksum files from the release Assets section.
  2. Extract only the Application Package ZIP, leave the Model & Data Package ZIP beside the extracted folder, and run setup-towerscout.cmd for first setup, prerequisite checks, checksum verification, asset import, and launch.
  3. Use start.bat -Engine docker -Gpu off for later direct launches.
  4. Configure Google Maps or Azure Maps.
  5. Define a search area and estimate tiles.
  6. Run detection, review results, add manual corrections, and export approved outputs.

Release Boundary

The current package path targets Windows 11 AMD64, single-user local use, CPU baseline operation, normal outbound internet access, the CPU Application Package on Docker Desktop as the primary controlled runtime, qualified Podman package-runtime support only where explicitly approved, and one site/user-owned restricted provider key.

GPU launch is optional and support-assigned. The default launch remains CPU-safe. The CPU package rejects -Gpu on; Docker GPU and Podman GPU use the CUDA package only after support validates the selected engine's NVIDIA container path and readiness reports selected_device=cuda.

Provider Keys

Browser map SDK keys are visible to someone with access to the running browser app. The package expects site/user-owned restricted keys and does not support unrestricted shared TowerScout project keys.
