Purpose

Applies to: The next documentation-aligned Windows release. Last reviewed: 2026-10-02.

TowerScout runs on one Windows 11 x64 computer and helps a person review aerial or satellite imagery for possible cooling towers. A machine-learning model suggests locations; a human reviews, corrects, and exports results. Suggestions are not confirmed towers and do not replace investigation or public-health judgment.

The User Makes Three Independent Choices

  1. Docker Desktop or Podman Desktop.
  2. CPU or a compatible NVIDIA GPU.
  3. Google Maps or Azure Maps.

These are supported options, not assignments. The final release record identifies exact tested engine/GPU combinations. The user/site owns provider accounts, billing, credentials, quotas, and usage rights.

What The Release Contains

  • CPU Application Package ZIP and checksum.
  • CUDA 12.8 Application Package ZIP and checksum.
  • One shared Model & Data Package ZIP and checksum.
  • A public record with authoritative SHA-256 values, pinned image digests, tested scope, source, and known limitations.

Download one Application Package variant. Docker or Podman downloads its digest-pinned image later. GitHub source archives are not installation packages.

Beginner Requirements

  • Windows 11 x64, hardware virtualization, WSL 2, and one running container engine.
  • The final release's RAM/disk minimum; plan at least 15 GB for CPU or 35 GB for CUDA unless it says more.
  • Internet access to the exact release, GHCR, and selected provider.
  • One Google or Azure credential; Python 3.12 only for the tested Podman provider path.
  • For GPU, a listed NVIDIA GPU/driver/engine combination and, for Podman, validated CDI.

Git, Node.js, Conda, a source checkout, and manual image download are not required for normal installation.

Security, Credential, And Privacy Boundaries

TowerScout uses one credential per provider in browser and application requests; the browser can see it. Use a dedicated limited account/key, API restrictions, quotas, alerts, monitoring, and rotation. Split-key, Microsoft Entra ID, or browser-secret requirements are outside the current configuration.

Unsigned package: Use supplied .cmd/.bat wrappers. They use a process-scoped execution-policy setting that does not change persistent policy. Signature-enforcing or organization-allowlisted endpoints are outside the standard claim. Never weaken endpoint protection, persistent policy, or TLS verification.

Verify each ZIP against its sidecar and the public release SHA-256 before extraction. Keep provider keys, private locations, raw logs/screenshots, traces, certificates, uploads, and exports out of public records.

Storage And Lifecycle

TowerScout binds to localhost. Each engine has separate named volumes for configuration, models, data, logs, sessions, temporary review data, uploads, and cache. Normal stop/start and reboot keep them; changing engines does not migrate them. Export important results because internal sessions are not backups.
