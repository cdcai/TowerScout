Document Metadata

Applies to: The next documentation-aligned Windows release package unless its release notes state otherwise.

Last reviewed: 2026-10-02.

Audience: Local IT, security, endpoint-management, and support staff.

Runtime scope: Windows 11 AMD64. Docker CPU is the default path; Docker GPU, Podman CPU, and Podman GPU are support-assigned.

The shipped Quick Start and Package Guide own exact user commands. The GitHub release record owns exact downloads, public SHA-256 values, image digests, qualified environments, and known limitations.

Decision Summary

  • TowerScout is a local browser application served from a digest-pinned Linux container. The normal URL is http://localhost:5000, with a loopback host binding.
  • The CPU Application Package on Docker Desktop is the normal path. CUDA and Podman require release-specific support assignment and validation.
  • Windows PowerShell scripts are intentionally unsigned. The supplied .cmd/.bat wrappers use a process-scoped execution-policy setting and do not change persistent policy.
  • Trusted-signature, WDAC/AppLocker, constrained-language, or organization-allowlisting requirements need a site-owned approval path and are outside the standard support claim.

Do not disable Defender/EDR, select Run anyway for unverified files, weaken machine-wide policy, or change persistent execution policy.

Runtime And Data Shape

The Application Package contains wrappers, Compose files, documentation, manifests, and notices. The separate Model & Data Package contains model weights and ZIP-code data. Docker or Podman pulls the exact digest-pinned image from GHCR.

Persistent named volumes hold configuration, assets, data, sessions, logs, uploads, caches, and temporary workflow state. They may contain sensitive configuration or investigation data and require site retention, access-control, backup, and disposal rules.

TowerScout results require human review and do not replace field verification or epidemiologic judgment.

Prerequisite Approval

Confirm Windows 11 AMD64, allowed WSL 2/virtualization, a modern browser, outbound HTTPS to the exact GitHub release/GHCR/selected provider, release-specific free disk, and a restricted site/user-owned provider key.

Docker Desktop must be installed, licensed, approved, and running for the default path. Podman requires the named machine and approved package-local Compose provider. GPU paths additionally require the release-qualified NVIDIA driver and Docker NVIDIA or Podman CDI checks. CPU fallback does not pass a required-GPU run.

Required Download And Integrity Flow

  1. Use a normal browser and the exact release link. Download one Application Package, its sidecar, the shared Model & Data Package, and its sidecar from release Assets.
  2. Before extraction or unblocking, compare each local SHA-256 with its sidecar and the value displayed in the authoritative release record.
  3. Use File Explorer Extract All on only the verified Application Package in a user-writable folder. Spaces are supported.
  4. Keep both ZIPs and both sidecars beside the extracted folder, then use setup-towerscout.cmd.

When co-location is not possible, quote both exact paths:

.\setup-towerscout.cmd -Engine docker -Gpu off `
  -PackageZip "C:\Approved Path\towerscout-<release-version>-cpu.zip" `
  -AssetZip "C:\Approved Path\towerscout-<release-version>-assets-<asset-version>.zip"

First Run And Readiness

setup_required is normal before a provider key is saved. The user enters the key privately through Setup Wizard or Settings. With a validated provider and imported assets, readiness should become ready.

Safe readiness evidence includes state, configured/not-configured booleans, engine, device policy, selected device, digest, loopback binding, and volume count—not keys, .env, raw traces, or screenshots.

Provider Accounts And Restrictions

The site/user owns provider enrollment, billing, quotas, restrictions, monitoring, and incident response. Browser SDK keys are client-visible by provider design. Use narrow restrictions and separate browser/server credentials where supported. Never commit or publish a key.

Network And TLS Inspection

Allow only destinations required by the selected release and provider. If validation reports an untrusted CA, use the package's documented support-directed TLS diagnostic and site-approved CA import. Keep dry-run certificate details private. Do not disable certificate verification or use an insecure TLS override.

Persistent Volumes, Backup, And Removal

Normal scripts\stop.cmd followed by start.bat recreates the container/network while preserving named volumes. Do not run a broad engine prune or remove named volumes during normal troubleshooting, upgrade, rollback, or evidence collection.

A reset/uninstall that deletes volumes is destructive and requires separate approval after required data and evidence are backed up.

Safe Support Evidence

Safe facts include the release URL/tag, filenames and hashes, Windows/engine/Compose versions, disk, redacted readiness, device/digest, loopback port, health, volume count, and a short error category.

Do not send provider keys, .env, raw logs/screenshots, private AOIs, provider URLs/bodies, browser traces, certificate identities, cached imagery, exports, volume contents, or local identifiers through public channels.

Stop And Escalate

Stop on absent/mismatched hashes, security-policy blocks, unavailable prerequisites, unsafe/mismatched ZIPs, corrupt assets, fatal, CPU selection during a required-GPU test, persistent provider failure, or non-loopback exposure.

Use a new empty working folder for each release, preserve volumes until an approved upgrade/rollback decision, confirm in-app Help matches the package, and verify final release links/hashes without a privileged GitHub session before broad distribution.
