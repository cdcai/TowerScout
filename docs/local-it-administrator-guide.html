Role And Scope

Applies to: The next documentation-aligned Windows release. Last reviewed: 2026-10-02. Audience: Local IT, security, and endpoint-management staff.

The user chooses Docker or Podman, CPU or a compatible NVIDIA GPU, and Google Maps or Azure Maps. Local IT confirms that the chosen prerequisites, network access, credential model, and unsigned-script boundary are permitted. The final release record limits support to exact tested combinations.

TowerScout is a local browser application served from a digest-pinned Linux container on loopback, normally at http://localhost:5000. Results require human review.

Approval Checklist

  1. Windows 11 x64, supported build, RAM, disk, hardware virtualization, and WSL 2 meet final requirements.
  2. The chosen engine is allowed: licensed/running Docker Desktop with WSL 2 Linux containers, or Podman Desktop with rootless podman-machine-default.
  3. Podman's tested path may install Python 3.12 and the package-local pinned Compose provider.
  4. GPU use matches the release's exact GPU/driver/engine matrix; Podman GPU includes NVIDIA Toolkit/CDI.
  5. Outbound HTTPS is permitted to the final GitHub release, GHCR, and selected provider endpoints.
  6. The site accepts one browser-visible credential per provider and owns billing, restrictions, quotas, monitoring, and rotation.
  7. Configuration, sessions, uploads, logs, caches, and exports have an approved custody/retention plan.

Normal package use does not need Git, Node.js, Conda, VS Code, or a source checkout. Host Python 3.12 is the tested exception for installing the package-local Podman Compose provider.

Unsigned Windows Boundary

TowerScout PowerShell scripts are intentionally unsigned. Supported .cmd/.bat wrappers start Windows PowerShell 5.1 with a process-scoped execution-policy argument, -ExecutionPolicy Bypass; they do not change persistent policy.

Stop: The standard package does not claim trusted Authenticode, WDAC/ AppLocker, constrained-language, antivirus/EDR exception, or organization-specific allowlisting compatibility. Do not disable those controls or select Run anyway for unverified bytes. A site that signs or repackages the package owns the changed bytes, new checksums, and qualification.

Required Download And Integrity Flow

  1. Use the public Releases page and the entry identified as the current supported final Windows release.
  2. Download one Application Package, its sidecar, the shared Model & Data Package, and its sidecar.
  3. Before extraction/unblocking, compare each calculated SHA-256 with its sidecar and the value displayed in the release record.
  4. Use File Explorer Extract All on only the verified Application Package in a user-writable folder.
  5. Keep both ZIPs and sidecars beside the extracted folder and use setup-towerscout.cmd.

When co-location is not possible, copy full paths from File Explorer, replace the bracketed descriptions, and keep the quotes and line-continuation backticks:

.\setup-towerscout.cmd -Engine docker -Gpu off `
  -PackageZip "[full path copied from the Application Package ZIP]" `
  -AssetZip "[full path copied from the Model & Data Package ZIP]"

setup_required is normal before provider setup. With assets and a validated provider, readiness should become ready.

Provider Credentials

TowerScout accepts one credential per provider and uses it for browser and application requests; it cannot use split Google keys or Azure Entra ID. If policy requires either, this release is not eligible. Otherwise use a dedicated limited project/account, API restrictions, quotas, alerts, monitoring, and rotation. See the credential walkthrough.

Do not request or publish a key, .env, provider response, browser trace, or key-bearing image.

Network And TLS Inspection

Allow only destinations listed for the exact release. The engine must pull the pinned GHCR image; TowerScout and the browser must reach the selected provider.

If provider validation reports an untrusted CA, run the documented helper without -Apply, review the proposed engine/provider/port/certificate target privately, obtain approval, and only then run the separate apply form. It imports an approved site CA into the selected engine's config volume. It cannot fix registry-pull trust or a blocked VM. Never disable TLS verification.

Persistent Data And Recovery

Each engine uses eight named volumes for configuration, models, data, logs, Flask sessions, session temporary data, uploads, and cache. Normal stop/start and reboot preserve them. Docker and Podman stores are separate; changing engines does not migrate data.

Users should export important results. Internal sessions are not backups. Do not use down -v, volume prune, machine reset, or blanket cleanup as routine recovery. Destructive reset/uninstall requires a separate approved procedure after backup.

Safe Evidence And Escalation

Safe facts include release/package name, local hash match result, Windows/engine/provider versions, disk, sanitized readiness, device/digest, loopback port, health, volume count, failed step, and non-secret error category.

Never post keys, .env, raw logs/screenshots, private locations, provider URLs/bodies, browser traces, certificate identities, cached imagery, uploads, exports, volumes, or local identifiers. The public issue tracker is not private or a guaranteed- response help desk. Local IT retains responsibility for managed controls and sensitive evidence.

Upgrade And Handoff

  • Use a new empty folder and exact next-release bytes; never mix versions.
  • Preserve volumes until the data owner approves upgrade/rollback actions.
  • Confirm running in-app Help matches the package and release.
  • Reverify hashes, image digest, engine/device, provider readiness, persistence, and required smoke path.
  • Retain source/SBOM/license/model/data/provider notices and the release manifest.
  • Verify public release links and displayed hashes without a privileged GitHub session.
