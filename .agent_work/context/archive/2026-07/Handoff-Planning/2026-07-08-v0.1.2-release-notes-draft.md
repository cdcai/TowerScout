# TowerScout v0.1.2

TowerScout `v0.1.2` is the validated stable release for the Windows package
path. It supersedes the earlier tag-only `v0.1.0` and `v0.1.1` identities,
which had published images but no final GitHub Release assets.

This release line carries the release-package launcher hardening and the
follow-on Docker image-identity fix so the packaged runtime, the package
metadata, and the engine-level running-image check align.

## What Changed Since v0.1.0-rc7.1

- Hardened the release-package launcher so package-managed `.env` values win
  over stale host `TOWERSCOUT_*` and TLS CA-bundle environment overrides.
- Added an engine-level running-image identity check to the packaged status
  path so package validation no longer has to trust readiness JSON alone.
- Fixed the Docker image-identity helper so packaged Docker launches report the
  running image identity reliably during final package validation.

## Known Non-Blocking Findings

- Google mode returns a generic error if "Find towers" is clicked before the
  user defines a search area or drawn boundary. Server-side bounds validation
  safely rejects the malformed request, and documented Google workflows with an
  explicit AOI passed. Workaround: draw or define a search area before running
  detection.
- `/favicon.ico` returns 404 because no favicon is packaged.
- Export/status notifications use blocking browser alerts; human workflows
  pass, but automation must dismiss the dialogs.
- Rapid automated config/save sequences can hit the shared per-IP rate limiter.
  User-paced interaction is unaffected.

## Support Boundaries

- The CPU package is the default for normal users.
- The CUDA package remains a support-assigned path for validated NVIDIA GPU
  workstations.
- Podman remains support-assigned and requires a running Podman machine plus an
  approved non-Docker-Desktop Compose provider.
- If provider validation fails on a managed network, use the packaged TLS
  repair flow or support guidance rather than editing package files manually.
