## 3 · The defect and the fix

**Defect:** `Get-TowerScoutRunningImageIdentity` wrapped each native inspect in a single pipeline expression — `(& docker inspect … | Select-Object -First 1)` — and checked `$LASTEXITCODE` afterwards. `Select-Object -First 1` stops the upstream pipeline as soon as it has one object, which can terminate/abandon the native command before PowerShell records its exit code; `$LASTEXITCODE` then holds a stale or termination value. Real `docker.exe` (slow, API round-trip) hits this window; instant test shims do not — which is why PR #47's shim-based tests passed while the real Docker smoke failed, and why no CI configuration could have caught this. The durable guarantee is the safe pattern itself, not test coverage.

**Fix (verified line-by-line at `c6f3ad0`):**
- Each inspect now runs to completion into a variable, `$LASTEXITCODE` is snapshotted **immediately** after the native call, and only then is `Select-Object` applied. This is categorically immune to the pipeline-stop interference.
- Applied consistently to both container inspects; the RepoDigests call already followed the safe capture-then-select shape and is unchanged structurally.
- A config-image inspect failure is now non-fatal (`ConfigImage` degrades to `""`) instead of nulling the whole identity — correct, since packages match on the digest path; a partial identity beats a silent `container_not_found`.
- Empty-output edge cases resolve safely (`@()[0]` → `$null` → `""` under the existing null-guards); WinPS 5.1-safe throughout; **the fix is engine-agnostic** — the podman path shares this code and gets the same hardening.
- New regression test `test_get_running_image_identity_uses_engine_inspect_successfully`: a PATH-shim `docker.cmd` answering `compose ps`, both container inspects, and the RepoDigests inspect; asserts the helper returns a non-null identity with the inspected ImageId preserved, through real PowerShell and real native invocation. Windows-only per the repo's validation model. Note the honest limit: a shim cannot reproduce the timing race — the test pins the happy path and the code pattern provides the guarantee; the real-container proof in the PR body (`Running image digest: sha256:6060e2d0…` on a live v0.1.1-cpu container) is the behavioral confirmation.
- Diff scope is exactly the fix + test (2 files); zero deletions elsewhere; no test weakened; base is current `main`; both workflows green at `c6f3ad0`; Windows slices listed in the PR body post-fix.
